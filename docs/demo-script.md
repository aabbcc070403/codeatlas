# CodeAtlas 演示脚本（5–8 分钟）

按 01-项目规格 第 14 节建议的时间结构编写：40s 背景 / 60s 导入覆盖 / 120s 审查证据 / 60s RAG 工具轨迹 / 60s 补丁对比 / 60s 评测限制，合计约 6 分 40 秒。每步给出具体操作路径与预期画面。

**演示前置（诚实标注）**：

- 启动方式见 README「快速开始」：`pnpm db:dev` → `pnpm db:migrate` → `pnpm seed` → `pnpm dev` → `pnpm worker:dev`，打开 <http://localhost:3100>。
- 本环境 `AI_PROVIDER=mock`：**审查结论、追问回答、补丁提案均为确定性 Mock 输出，界面全程带「Mock（非真实模型）」标注**。真实模型调用未验证（无凭证，代码按真实 SDK 路径实现）。
- 演示中的**数字类内容（评测指标、风险公式）来自真实静态评测记录**（见 `docs/evaluation.md`）；静态规则命中与证据校验为真实代码路径。
- 演示 ZIP 自备：建议含 1 个带 `dangerouslySetInnerHTML` 的 TSX、1 个含动态求值的 JS、1 个缺 key 的列表组件。若使用录制回放，必须在画面上标注「回放」。

---

## 第 1 段（约 40 秒）——问题背景

**操作**：停留在 `/login` 页，口述背景。

**讲稿要点**：学生和小团队缺少审查人员；规则工具解释不贴近上下文，通用聊天工具引用难核实。CodeAtlas 的回答方式：确定性静态规则打底 + 受预算约束的 AI + **每条结论必须有可点击核验的路径 / 行号 / 引文证据**；不宣称「证明代码安全」「发现全部 Bug」。

**预期画面**：登录页访问码输入框；页头「CodeAtlas 码鉴 · 证据驱动的 AI 项目体检」。

## 第 2 段（约 60 秒）——导入与覆盖

**操作**：

1. 输入演示访问码（本地默认 `codeatlas-demo`）→「进入工作台」→ `/projects`。
2. 「项目名称」填「校园活动平台」→「新建项目」→ 点击项目进入 `/projects/[id]`。
3. 上传准备好的 ZIP → 等待「导入完成：」摘要出现。
4. 展开忽略明细，点开文件树中任一文件查看只读预览。

**预期画面**：导入摘要显示文件数 / 可分析文件数 / 忽略列表及原因 / 脱敏记录；界面提示「外发模型说明」（用户主动选择云端 AI 才发送代码片段）。

**讲稿要点**：路径穿越 / 炸弹 / 符号链接防护；疑似密钥等长脱敏；忽略策略逐条可见。

## 第 3 段（约 120 秒）——审查与证据

**操作**：

1. 快照卡片点「开始审查」→ 跳转 `/scans/[id]`（不勾选云端 AI → 纯静态扫描）。
2. 观察阶段进度 ingest→index→static→…→report 与实时事件（SSE）；等待「已完成」。
3. 看风险指数卡片（含公式 `riskIndex = min(100, 20×critical + 10×high + 4×medium + low)` 与「待核查不计入」口径提示）、静态覆盖、问题列表。
4. 点击首条「候选 HTML 注入入口」进入 `/scans/[id]/findings/[findingId]`：中间只读代码（行号 1 起始、主引用高亮），右侧证据面板（触发条件 / 影响 / 依据 / 建议、规范引用的标题 / 版本 / 来源链接）。
5. 点「确认问题」反馈；再打开一条 medium 问题点「标记误报」，回到扫描页看风险指数联动下降。

**预期画面**：问题列表每条带 severity / category / 来源（静态规则）/ 证据状态徽章；反馈后风险指数即时更新。

**讲稿要点**：静态命中确定性可复现（真实代码路径）；候选问题标 needs_review 不冒充确认漏洞；needs_review 不计入风险指数。

## 第 4 段（约 60 秒）——RAG 与工具轨迹

**操作**：

1. （可选）回项目页，上传项目自有 Markdown 规范 → `/knowledge` 展示索引状态。
2. 回到问题详情页右栏「追问」面板，输入：「这段输入经过净化了吗？」回车提交。
3. 等待回答出现：注意「Mock（非真实模型）」徽章、模型请求 / 工具调用次数、检索模式。
4. 展开回答中的代码引用，点击 → 中间代码区定位到对应行。
5. （若该扫描启用了 AI 阶段）回 `/scans/[id]` 指向「工具轨迹」面板：仅展示工具名 / 输入摘要 / 耗时 / 成功状态。

**预期画面**：回答旁标注 Mock 与调用计数；引用点击定位；无任何思维链展示。

**讲稿要点**：追问被限制在当前问题 + 当前快照 + 规范库，只有 read_file / search_code / list_imports / retrieve_guidelines 四个受控只读工具（无终端 / 联网 / 写文件）；引用必须通过「完整读取覆盖 + 严格引文匹配」校验，检索只能引用本轮实际返回的规范条目；证据不足时明确说不足。**此环节为 Mock 演示**；预置 30 条版本化规范与双路检索（pgvector + 词法 RRF 融合）为真实实现。

## 第 5 段（约 60 秒）——补丁与对比

**操作**：

1. 问题详情页右栏「修复补丁提案」→ 点生成 → 等待 diff 出现。
2. 指出三项分开的验证状态：可应用 / 语法（基线→补丁后错误数）/ 测试恒为 `not_run`（附「请在你的环境中自行测试」）；点「下载」得到 `.patch` 附件。
3. 回项目页上传修复版 ZIP →「开始审查」→ 等待第二次扫描「已完成」。
4. 项目页点「快照对比」→ `/projects/[id]/compare` 默认选最早 / 最新两次扫描 → 点「查看对比」。

**预期画面**：diff 逐行着色 + **「Mock 示例提案，非真实 AI 修复」标注**；无效提案不给下载。对比页四类变化徽章（新增 / 仍存在 / 未再检出 / 不可比较）与逐条列表；「未再检出 ≠ 已验证修复」固定说明可见。

**讲稿要点**：补丁不写入上传原件、不提交远程仓库，只在内存副本应用后导出；命中脱敏区间的补丁禁止导出；对比匹配不依赖行号（规则 + 路径 + 符号 + 代码哈希），旧问题所在范围本次未覆盖时归入不可比较而非「未再检出」。

## 第 6 段（约 60 秒）——评测与限制

**操作**：

1. 用管理员访问码登录（本地默认 `codeatlas-admin`）→ `/evaluation`。
2. 指出数据集概况：`v1-cd06ca6f · 24 项目（12+12）· 6 类 · 16/8 划分`；小样本口径声明与「真实模型评测未执行」说明。
3. 选 `static_only` + 开发集 → 运行 → 2 秒轮询至「已完成」→ 指标卡 Precision / Recall / F1 = 1.000（TP 9、FP 0、FN 0）、证据有效率 100%、p50/p95。
4. 指出消融表与逐项目表：每行可点「查看」跳回 `/scans/:id` 回溯原始扫描。

**预期画面**：指标卡数字与 `docs/evaluation.md` 一致；demo 会话触发评测会如实显示 403 / 无权限（可另开无痕窗口演示权限隔离）。

**讲稿要点与诚实限制（收尾）**：

- **static_only 指标是真实静态规则在真实数据集上的确定性结果**（真实代码路径 + 真实运行）；满分的含义是「样例集与规则集对齐（生成器强校验）」，不代表真实项目准确率。
- **llm_no_rag / hybrid_rag 的评测与演示均为 Mock 管线**（provider=mock 逐项标注）；真实模型调用未验证——无凭证，代码按真实 SDK 路径实现，凭证就绪后先 `pnpm doctor` 自检再小样本冒烟。
- Docker / Compose 文件已提供但**本机未验证**（无 Docker）；生产 PostgreSQL 上的租约 / 额度原子性测试待首次部署重跑。
- 收尾一句话：CodeAtlas 的价值不在「AI 有多聪明」，而在**每条结论可核验、每个数字可回溯、每个限制都如实标注**。
